# Фаза 1. План разработки

**Версия:** 6.1
**Дата обновления:** 2026-11-24
**Статус:** Спираль 7 (Макет MG → ERP) в работе.

## Цель
Реализовать MVP платформы.

## Что должно быть в MVP
1. Создание административной структуры.
2. Создание пользователей.
3. Телефонный справочник.
4. Делегирование.
5. Создание проектов.
6. Редактирование проектов.
7. Создание Мастерграфиков.
8. Редактирование Мастерграфиков (черновик/чистовик).
9. **Базовый универсальный бизнес-МС** (ЛГ).
10. Просмотр МГ и ЛГ только для чтения.
11. Отчёт в окне МГ.
12. Discovery service.
13. Система уведомлений.
14. Техническая поддержка.
15. **Треды обсуждения задач МГ** (Спираль 8).
16. **Ревизия DELEGATION_SERVICE и NOTIFICATION_SERVICE** (Спираль 8).
17. **Инициализация ERP** (Спираль 11): BDERE, телефонный справочник, workflow.
18. **CI/CD** (Спираль 12): персональный `.env`.
19. **Мобильный клиент** (Спираль 13).

## Примечания
1. МГ и ЛГ открываются в отдельном окне (отдельный процесс).
2. МГ поддерживает подпроекты.
3. API для автоматического наполнения графиков.
4. Сбор уведомлений в отдельном процессе.
5. После MVP — разделить на 2 репозитория (клиент, МС).
6. CI/CD.
7. **TimelineController** — единый источник displayStart/End/dayWidth.
8. **Целевой период проекта** — target_start_date/target_end_date.
9. **Wizard инициализации МГ**.
10. **Согласование МГ**.
11. **Zoom level «Месяц»**.
12. **Явное завершение МГ-задачи из ЛГ** (кнопка «Завершить»): активна, когда все задачи ЛГ со сроками завершены и нет задач без сроков; по подтверждению — МГ-задача получает статус «Выполнено». Автоматическое завершение (когда все ЛГ-задачи Completed) — **отменено** (BUS `_compute_forecast` не ставит `status = 1`).
