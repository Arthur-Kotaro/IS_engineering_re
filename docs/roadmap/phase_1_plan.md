# Фаза 1. План разработки

> Источник: первый присланный файл + новое знание про базовый
> универсальный бизнес-МС.

## Цель

Реализовать MVP платформы.

## Что должно быть в MVP

1. Создание административной структуры.
2. Создание пользователей.
3. Телефонный справочник.
4. Делегирование.
5. Создание проектов.
6. Редактирование проектов.
7. Создание Мастерграфиков.
8. Редактирование Мастерграфиков (2 режима: Черновик и Чистовик.
   Чистовик с момента утверждения графика проекта. В режиме
   черновика не фиксируются переносы вех и задач).
9. **Базовый универсальный бизнес-МС** для редактирования локальных
   графиков (под каждую группу задач развёртывать универсальный МС).
   ЛГ позволяет создавать отчёт, который можно просмотреть из
   контекстного меню задачи из МГ при наличии прав).
10. Режим просмотра МГ и ЛГ только для чтения с контролем прав доступа.
11. В окне Мастерграфика кнопка с «гиперссылкой» под названием
    «Отчёт». По клику открывает новую вкладку. В ней отчёт об
    актуальном состоянии (пройденные и оставшиеся вехи, группы,
    количество задач и диаграммы с анализом задач (выполнены,
    запланированы, имеют риски). Информация о том, на сколько
    сместились сроки проекта с момента утверждения МГ).
12. Discovery service для развёртывания универсального бизнес-МС.
13. Система автоматической отправки уведомлений.
14. Создание и обработка запросов в службу технической поддержки
    (БД с типовыми запросами на обслуживание. Передача данных
    пользователя, обратившегося в поддержку).

## Примечания

1. МГ и ЛГ открываются в отдельном окне без фокуса. Количество
   окон не ограничено (до 10). Каждое окно — отдельный поток
   (или процесс).
2. МГ поддерживает функционал подпроектов. Подпроект имеет свой МГ,
   команду, типологию и пр. В главном МГ есть отдельная полоса вех
   для подпроектов, которую можно показать/скрыть. Модель
   зависимостей вех: вехи главного МГ зависят от вех подпроектов
   и указанных пользователем задач.
3. В МС МГ есть API для автоматического наполнения графиков
   сторонними МС.
4. Сбор уведомлений клиента в отдельном процессе со всплывающими
   уведомлениями. Работает независимо от основного окна.
5. После реализации MVP разделить проект на два репозитория:
   для клиента и МС.
6. Разрабатывать CI/CD инструменты.

## Базовый универсальный бизнес-МС

> См. также `strategy.md`.

**Было:** уникальные микросервисы под каждое подразделение,
обслуживающие специфические потребности.

**Стало:** базовый универсальный бизнес-микросервис, решающий
типовые задачи, общие для всех подразделений предприятия.
Без специализации на конкретной отрасли.

При этом в системе **умышленно** разворачивается несколько
совершенно одинаковых с точки зрения программного кода экземпляров
такого сервиса:

- каждый экземпляр может быть доработан и дополнен специфическим
  функционалом независимо от других;
- специализация может создаваться «на лету» — после развёртывания
  системы и выхода в эксплуатацию;
- Discovery service находит экземпляры и маршрутизирует запросы.
