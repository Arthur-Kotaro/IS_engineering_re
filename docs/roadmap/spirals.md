## Отменено

- **Модель `owner/manager/editor/viewer`** в Project Service.
- **`head_id` у пользователя** — не нужен. Иерархия — через `departments.parent_dept_id`.
- **Композиция `direct OR subordinate OR delegated`** — не реализована.
- **Роль X («Директор по менеджменту проектов»)**.
- **`upp_head`** — дубликат `proto_production_head`.

## Правило спирали

**Спираль 6.6 — фундаментальная переработка.** После неё:
- User Service: роли + должности + подразделения.
- Project Service: справочник проектных ролей.
- Navigation Service: 3 таблицы плиток.
- Auth Service: `X-User-Position` + `X-User-Role`.
- Client: обновить под новую модель.

**Только после этого — MG Service.** (Спираль 7 начата, так как 6.6 стабилизирована для MVP).

## Требования к разработке

1. **C/C++ строго в стиле Allman.** Фигурные скобки на новой строке.
2. **Файл > 450 строк → делим на несколько файлов.**
3. Код на Python — PEP 8, но без фанатизма.
4. Одна порция = одна проверка.
5. Новые файлы и перезаписи — через `cat > файл <<'EOF'`.
6. Точечные правки в больших файлах — вручную в редакторе.
7. `sed`, `awk` — не использовать.
