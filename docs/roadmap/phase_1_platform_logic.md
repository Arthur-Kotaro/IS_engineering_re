## 2. Телефонный справочник

Нужно добавить справочник пользователей. В navigation service
добавить универсальные плитки (для всех пользователей):
«Справочник пользователей», «Техническая поддержка»
(поддержку реализуем позже).

Справочник состоит из вертикальной левой панели и основной области.

### Левая панель

Используется для поиска пользователя и содержит:
- 3 поля ввода ФИО;
- выпадающий список для выбора должности;
- 2 поля ввода: кода подразделения пользователя и названия подразделения;
- кнопку «Поиск».

### Основная область

- Отображается в области вертикальной прокрутки. Левая зафиксирована.
- Отражает иерархическую структуру подразделений в виде выпадающих
  списков, которые можно сворачивать или разворачивать по нажатию
  на значок «+» или «-».
- При сворачивании подразделения перестают отображаться вложенные
  подразделения и визитки.
- Ниже строки с названием подразделения указывается визитка
  (описание профиля) руководителя подразделения.
- При разворачивании списка наиболее глубокой вложенности
  отображаются визитки пользователей. Например, при разворачивании
  списка членов бюро показываются визитки начальника бюро и
  сотрудников бюро.

### Поведение

- Пользователь может просматривать структуру и визитки пользователей
  в основной области.
- Если пользователь воспользовался поиском из левой панели и поиск
  нашёл пользователей, соответствующих запросу, в основной области
  автоматически сворачиваются все подразделения, за исключением тех,
  в которых числятся найденные пользователи.

### Кэширование (Спираль 11)

Данные справочника меняются редко, но читаются часто.
Кандидат на кэширование:
- **Redis DB 2** (кэш — резерв, см. `tech-stack.md`).
- **Защита от stampede** (cache stampede / thundering herd).
  При промахе кэша только один запрос перечитывает данные из БД,
  остальные ждут результат. Реализация: `cachefence` или ручной
  лок через `SET NX` в Redis.
- **Инвалидация:** при изменении данных пользователя (через
  `USER_service`) кэш справочника инвалидируется.

## 3. Треды обсуждения задач МГ (Спираль 8)

> Не мессенджер. Тред — структурированная запись управленческих
> решений по задаче.

### Модель

- **Одна задача = не более одного треда.** Защита от путаницы.
- **Тред создаётся по необходимости** (не для всех задач).
- **Участники:** создатель (CVE/IPP) приглашает сразу или позже.
  Новые участники видят всю историю с момента создания.
- **Содержание:** только текст. Короткие и сухие сообщения:
  постановка целей, подтверждение/отказ, пояснения ключевых
  проблем и рисков.
- **Никаких** стикеров, смайликов, голосовых, фото, видео.
- **Привязка:** `project_id` + `task_id`. Из треда можно перейти
  к графику и задаче.
- **Права:** проверка «является ли пользователь участником треда»
  (не привязано к времени отправки сообщения).

### Причина ограничений

- Проще в реализации.
- Чище для AI Manager (текст легче анализировать).
- Соответствует управленческой дисциплине (CVE обсуждает задачу
  с конкретными людьми, а не со всеми подряд).

### Discussion service

- Отдельный микросервис.
- Хранит треды (один на задачу), участников, сообщения.
- Привязка к `project_id` + `task_id`.
- WS для real-time (клиент — отдельный процесс + окно).

### Ревизия DELEGATION_SERVICE и NOTIFICATION_SERVICE

- **DELEGATION_SERVICE:** завершение Спирали 4 (имперсонация
  требует доработки после 6.6). Опора на карту делегирования
  из документации.
- **NOTIFICATION_SERVICE:** уведомления о новых сообщениях
  в тредах. Опора на карту уведомлений из документации.

## 4. Инициализация ERP (Спираль 11)

- **BDERE (Block Diagram Editor Rendering Engine):**
  реализовать блочный редактор (ADR 0014). Использовать для
  экспресс-создания административной структуры при вводе
  в эксплуатацию.
- **Телефонный справочник:** endpoint для чтения в `USER_service`,
  кэш (Redis DB 2), защита от stampede.
- **Workflow:** создание пользователей, CRUD проектов через GUI
  (`PROJECT_service`).

## Требования к разработке

1. **C/C++ строго в стиле Allman.** Фигурные скобки на новой строке.
2. **Файл > 450 строк → делим на несколько файлов.**
3. Код на Python — PEP 8.
4. Одна порция = одна проверка.
5. Новые файлы и перезаписи — через `cat > файл <<'EOF'`.
6. Точечные правки в больших файлах — вручную в редакторе.
7. `sed`, `awk` — не использовать.
