# Правило ведения документации

**Версия:** 6.0
**Дата обновления:** 2026-11-14

> Источник: первый присланный файл (п.3).

## Разбиение спиралей на фазы и блоки

- Список спиралей разбивается на **фазы** и **блоки**.
- Каждый блок соответствует **одному диалогу**.
- При обновлении документации ставится **timestamp**, показывающий,
  на какую дату выполнен блок спиралей.
- Это позволяет отслеживать **темп развития проекта**.

## Следствие

`roadmap/progress.md` — живой документ. Даты появляются по мере
работы. Прочерк — дата ещё не наступила или не зафиксирована.

## Требования к разработке, влияющие на документацию

1. **C/C++ строго в стиле Allman.** Фигурные скобки на новой строке.
   При добавлении примеров кода в документацию — соблюдать.
2. **Файл > 450 строк → делим на несколько файлов.**
   При описании больших файлов в документации — указывать,
   что они разбиты (или должны быть разбиты).
3. Код на Python — PEP 8.
4. Одна порция = одна проверка.
5. Новые файлы и перезаписи — через `cat > файл <<'EOF'`.
6. Точечные правки в больших файлах — вручную в редакторе.
7. `sed`, `awk` — не использовать.

## Формат обновления документов

- **Полная перезапись** — через `cat > файл <<'EOF'`.
  Используется чаще всего.
- **Точечные правки** — вручную в редакторе.
  Исключение — очень большие файлы с простыми ручными правками.
- Timestamp ставится в шапке документа при каждом обновлении.
