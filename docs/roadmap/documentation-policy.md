# Правило ведения документации

> Источник: первый присланный файл (п.3).

## Разбиение спиралей на фазы и блоки

- Список спиралей разбивается на **фазы** и **блоки**.
- Каждый блок соответствует **одному диалогу**.
- При обновлении документации ставится **timestamp**, показывающий,
  на какую дату выполнен блок спиралей.
- Это позволяет отслеживать **темп развития проекта**.

## Следствие

`roadmap/progress.md` — живой документ. Даты появляются по мере
работы. Прочерк — дата ещё не наступила или не зафиксирована.
