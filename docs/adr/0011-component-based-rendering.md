# ADR 0011. Компонентный подход к рендерингу форм

**Дата:** 2026-10-12
**Status:** Accepted

## Контекст

До этой порции рендеринг-движок клиента (`QmlObjectFactory` +
`WidgetGenerators.cpp`) генерировал **монолитный inline-QML** для каждого
виджета. Каждый генератор возвращал длинную QML-строку, полностью
описывающую виджет: заголовок, поле ввода, логику фильтра, обработчики
событий.

Такая архитектура не масштабируется:

- для виджета с фильтром и списком (SelectField, MultiSelectField)
  генератор превращался в сотни строк QML-шаблона;
- любое изменение поведения (например, «добавить фильтр в список
  должностей») требовало править QML-строку внутри C++;
- нельзя было повторно использовать виджет в другом контексте;
- внутреннее состояние (текущий фильтр, выбранные значения) хранилось
  в замыканиях QML-строки и было неуправляемым.

Требование от 2026-10-12 (первая порция диалога):

> «Рендеринг-движок должен быть достаточно умным и гибким,
>  чтобы отображать любые сложные страницы».

## Решение

Ввести **библиотеку QML-компонентов** `BaseWidgets 1.0`, размещённую
в `CLIENT/production_client/qml/widgets/`.

Генераторы возвращают **короткий inline-QML**, который инстанцирует
компонент из библиотеки и передаёт ему спецификацию:

```qml
SearchableListSingle {
    label: "Отдел"
    fieldId: "dept_id"
    required: false
    options: [...]
    Layout.fillWidth: true
    Layout.maximumWidth: 800
}
Первый набор компонентов:

    SearchableListSingle — одиночный выбор через радиокнопки
    с фильтром (для отдела, должности).

    SearchableListMulti — множественный выбор через чекбоксы
    с фильтром (для ролей).

    SearchableSelect — простой ComboBox с фильтром (заготовка
    на будущее).

Регистрация модуля — через qmlRegisterType(QUrl(...), "BaseWidgets", 1, 0, "...")
в main.cpp. QML-файлы добавлены в QML_FILES модуля ProductionClient
в CMakeLists.txt.
Последствия

Положительные:

    Один компонент — одна ответственность. Логика фильтрации,
    состояние выбора, отправка события — внутри компонента.

    Генераторы стали короткими: описание виджета в спецификации
    (label, fieldId, options) + одна строка ссылки на компонент.

    Компонент можно использовать в любой странице и в любом
    контексте (не только в HR-формах).

    Расширение: новые компоненты добавляются в библиотеку,
    без правки C++.

    Дизайн-система: цвета, скругления, анимации — внутри компонентов,
    единообразно.

Отрицательные:

    Появляется слой QML-файлов, который нужно сопровождать
    (документация, тесты).

    Регистрация через qmlRegisterType не даёт полного автодополнения
    в Qt Creator, qmltypes не генерируется автоматически. Для проекта
    такого масштаба — приемлемо.

    Регистрация модуля требует, чтобы main.cpp вызывал
    qmlRegisterType до engine.load(...). Это соблюдено.
