# ADR-0004: Три типа делегирования

## Статус
Accepted

## Дата
2026-09-26

## Контекст

Требуется механизм временной передачи полномочий между пользователями.
Иерархия в User Service: `head_id`, 1 уровень, не транзитивно.

## Решение

Три типа делегирования:

| Тип | Инициатор | Получатель | Основание | Хранение |
|---|---|---|---|---|
| Обратное | Начальник | Прямой подчинённый | Иерархия (head_id) | НЕ хранится |
| Прямое | Начальник (сам) | Прямой подчинённый | Явный акт | Хранится (direct) |
| Временное | Начальник | Подчинённый Б (полномочия А) | Явный акт | Хранится (temporary) |

### Обратное

- Не требует акта. Начальник всегда может войти как подчинённый.
- Реализуется через `POST /internal/auth/impersonate` (User Service).
- Проверка: `subordinate.head_id == recipient.user_id`.
- В Delegation Service **не хранится**.

### Прямое

- Начальник передаёт **свои** полномочия подчинённому.
- `initiator_id = delegator_id = начальник`.
- `delegate_id = подчинённый`.
- Условия: delegate — прямой подчинённый, правило роли разрешает.
- Один активный pair. `max_delegations` ограничивает.
- Хранится как `delegation_type = 'direct'`.

### Временное

- Начальник передаёт полномочия подчинённого А подчинённому Б.
- `initiator_id = начальник`.
- `delegator_id = А` (донор).
- `delegate_id = Б` (получатель).
- `main_delegate_id = А` (для справки).
- Условия: А и Б — прямые подчинённые начальника.
- Хранится как `delegation_type = 'temporary'`.

## Правила

1. Реципиент — всегда прямой подчинённый инициатора.
2. Один активный реципиент на одно делегирование.
3. Передача дальше запрещена: реципиент не может создать делегацию.
4. Рекурсия запрещена: в режиме имперсонации создание делегаций отклоняется 403.
5. Отзыв: `initiator_id` или `is_super_admin`.
6. При увольнении/блокировке донора — ликвидация через событие `user.events` (Redis pub/sub).

## События

Delegation Service подписан на `user.events` (Redis DB 3):
- `user.deleted` → revoke все активные делегации донора.
- `user.blocked` → revoke все активные делегации донора.

## Что удалено из старой модели

- Тип `REVERSE` — заменён на обратное делегирование через иерархию.
- `Enum` для `delegation_type` — заменён на `String(20)` + CheckConstraint.
- `Enum` для `status` — заменён на `String(20)` + CheckConstraint.
- Хардкод `admin`/`manager` в `ValidationService` — заменён на `RuleRepository.find_best_rule(roles)`.
- `session_id` в history — не используется.
