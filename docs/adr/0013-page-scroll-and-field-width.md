# ADR 0013. Скроллбар вкладки и ограничение ширины полей ввода

**Дата:** 2026-10-12
**Status:** Accepted

## Контекст

Требования от 2026-10-12:

> 1. У страницы есть скроллбар.
> 2. Скроллбар на всю вкладку. Скроллбар для страниц должен
>    стать элементом интерфейса страниц по умолчанию. Если страница
>    умещается в окне — скроллбар должен скрываться.
> 3. Если страница содержит списки — в списке свой скроллбар.
> 4. Обрати внимание, что у всех полей ввода значений на странице
>    выравнивание по ширине. Это порождает проблему — если указатель
>    мыши попадает на вложенный скроллбар (например, список отделов),
>    то нет возможности мышью прокрутить страницу. Лучше явно задать
>    width для полей ввода и аналогичных виджетов внутри контейнера.
>    Учти, что бывают исключения. Например, если в контейнере
>    содержатся графики, круговые диаграммы и пр. инструменты
>    инфографики — эти элементы инфографики ограничивать по ширине
>    не нужно.

## Решение

### Скроллбар вкладки

- `TabContent.qml` использует `Flickable` вместо `Item`,
  с `ScrollBar.vertical.policy: ScrollBar.AsNeeded`.
- `Flickable.contentHeight` привязан к сигналу
  `JsonUiRenderer::contentHeightChanged(int)`, который эмитится
  после рендера. Прямая привязка к `uiContainer.childrenRect.height`
  не работает: в момент рендера дети ещё не рассчитаны, `childrenRect`
  возвращает 0.
- Корневой `ColumnLayout` внутри `uiContainer` получает
  `objectName = "rootLayout"` (в `JsonUiRenderer::render`), чтобы
  его можно было найти из QML.
- Внутри списков (`SearchableListSingle`, `SearchableListMulti`)
  — свой `ScrollBar.AsNeeded`.

### Ограничение ширины полей ввода

- Все генераторы полей ввода (`generateTextField`,
  `generateSearchField`, `generateEmailField`, `generatePasswordField`,
  `generateSelectField`, `generateMultiSelectField`,
  `generatePushButton`) добавляют `Layout.maximumWidth: 800` в свой
  inline-QML.
- **Инфографика** (`Chart*`, `QTableWidget`) — **не ограничивается**:
  занимает всю доступную ширину.
- Ширина 800 px — хардкод на этом этапе. Возможно вынесение
  в `GlobalSettings` позже.
- `QQuickItem::setProperty("Layout.maximumWidth", ...)` **не работает**:
  `Layout.maximumWidth` — attached property, не обычное свойство
  объекта. Поэтому ограничение задаётся в QML-коде генератора.

## Последствия

**Положительные:**

- Скроллбар вкладки — единообразное поведение для всех страниц.
- Колесо мыши работает на всей странице, включая пустую полосу
  справа от полей.
- Поля ввода занимают разумную ширину, не растягиваются
  на широких мониторах.
- Инфографика (графики, диаграммы, таблицы) — на всю ширину, как
  и должно быть.

**Отрицательные:**

- `Layout.maximumWidth: 800` дублируется в 7 генераторах.
  При изменении значения — правка в 7 местах. Позже вынести
  в `GlobalSettings.maxFieldWidth`.
- `Flickable.contentHeight` зависит от сигнала из C++. Порядок
  «сначала рендер, потом высота» — критичен. Если рендер
  асинхронный (данные из `DataManager`), высота обновится
  только после `dataReady`.
