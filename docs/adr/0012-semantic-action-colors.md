# ADR 0012. Семантический слой цветов action-элементов

**Дата:** 2026-10-12
**Status:** Accepted

## Контекст

До этой порции `Colors.qml` содержал **плоский набор цветов**:
`background`, `surface`, `text`, `button`, `buttonHover`, `error`,
`warning`, `success`. Каждый элемент интерфейса обращался к этим
цветам напрямую.

С появлением кнопки «Назад» (порция 4b, 2026-10-12) стало ясно,
что нужен **семантический слой** для action-элементов —
интерактивных кнопок, чьё поведение отличается от обычных кнопок
(они имеют состояние «активна / неактивна» и особую цветовую
схему).

Требование от 2026-10-12:

> «Плитки и кнопка „назад“ будут не единственными анимированными
>  элементами интерфейса. Поэтому очень может быть, что не только
>  кнопка „назад“ будет использовать эти цветовые схемы.
>  У каждой темы будет свой набор таких полей.»

## Решение

Добавить в `Colors.qml` **четыре семантических цвета**
для action-элементов:

| Свойство | Смысл |
|---|---|
| `actionBg` | Фон активной action-кнопки (= цвет плитки) |
| `actionFg` | Иконка/треугольник на активной action-кнопке (темнее `actionBg`) |
| `actionDisabledBg` | Фон неактивной action-кнопки (бледнее `actionBg`) |
| `actionDisabledFg` | Иконка на неактивной action-кнопке (бледнее `actionFg`) |

Каждая из **6 схем** (dark 0/1/2, light 0/1/2) получает свой
набор значений (`darkActionBg0`, `darkActionBg1`, …, `lightActionFg2`).
При переключении темы `updateColors()` присваивает активным
семантическим свойствам значения выбранной схемы.

Кнопка «Назад» в `TabContent.qml` использует:
- `actionBg` / `actionDisabledBg` — фон;
- `actionFg` / `actionDisabledFg` — цвет треугольника.

## Последствия

**Положительные:**

- Семантика вместо конкретики. Action-элемент не знает, что он
  «кнопка назад». Он знает, что он action-элемент.
- Масштабируется на будущие элементы (кнопка «Вперёд», «Обновить»,
  «Сохранить» в тулбаре и т.д.) без добавления новых цветов.
- Единообразие с плитками (плитки — тоже action-элементы
  навигации; их цвет совпадает с `actionBg`).
- Каждая схема независима: разработчик добавляет новую тему,
  задавая 4 новых значения.

**Отрицательные:**

- `Colors.qml` вырос: было ~40 свойств, стало ~80.
  Читаемость падает без структурирования. Сейчас структурировано
  комментариями по схемам (Dark 0/1/2, Light 0/1/2).
- Значения `action*` подобраны вручную. При изменении палитры
  нужно обновлять 4×6 = 24 значения. Можно автоматизировать
  (функция `darker()` / `lighter()`), но пока — ручная подстройка.
