# ADR-0003: SQLite как хранилище Navigation Service

## Статус
Accepted

## Дата
2026-09-26

## Контекст

Navigation Service хранит плитки (tiles) — конфигурацию рабочего стола пользователя: какие действия видны, по каким ролям, с какими endpoints.

Особенности:
- Объём — десятки строк.
- Изменения — редкие.
- Чтение — часто (на каждый логин пользователя).
- Данные — конфигурация, не бизнес-данные.
- Сервис — инфраструктурный.

## Решение

Оставить SQLite.

Причины:
- Плитки — конфигурация. Полноценная СУБД избыточна.
- Сервис не зависит от Postgres.
- SQLite быстрее для чтения малых данных.
- Простое резервное копирование (один файл).
- При появлении user_tile_preferences — SQLite справится до 500 пользователей.

## Ограничения

1. Не масштабируется горизонтально.
2. Блокировка при записи (не критично для редких изменений).
3. Миграции через Alembic.

## Что делать

1. navigation.db — в .gitignore (после перехода на desktop).
2. Alembic для миграций.
3. user_tile_preferences — оставить как заготовку, модель когда понадобится.

## Триггеры для пересмотра

Горизонтальное масштабирование, > 100 плиток, > 10 изменений/сек, мультитенантность.
