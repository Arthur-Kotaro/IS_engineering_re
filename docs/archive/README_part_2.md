## ЧАСТЬ 8. ОСНОВНОЙ ПРОЦЕСС

### 8.1. Пошаговый процесс

| № | Этап | Участники | Результат |
|---|------|-----------|-----------|
| 1 | Запрос на изготовление лота | Проект → прото-РП | Запрос + состав КИ (3 раздела: покупные, серийные, производимые) |
| 2a | Проработка состава | Группа проработчиков | Валидированный состав (итерации) |
| 2b | Технологическая проверка | Технологи | Подтверждение техвозможности / запрос КД |
| 3 | Прогноз сроков | Плановик | Ориентировочные сроки |
| 4 | Условия выпуска ТЗ | прото-РП | 1. Валидированный состав; 2. Техвозможность; 3. Ориентировочные сроки |
| 5 | Выпуск ТЗ | прото-РП | ТЗ |
| 6 | Согласование ТЗ | Экономист проекта + гл. инженер | ТЗ действительно |
| 7 | ТЗ — триггер | — | Запускаются: ТД, заявки на КИ, наряд-заказы |
| 8 | Разработка ТД | Технологи (Бюро сборки) | ТД |
| 9 | Распределение ТД | Плановик → мастера | ТД по цехам, участкам, станкам |
| 10 | Изготовление в цехах | Цеха УПП | Производимые КИ |
| 11 | Заявки на КИ | Бюро обеспечения сборки → СТС | Заявки |
| 12 | Наряд-заказ в серийное производство | Экономист УПП | Наряд-заказ |
| 13 | Обеспечение серийными КИ | Бюро серийных КИ (СТС) | Накладные, КИ на склад |
| 14 | Обеспечение покупными КИ | Бюро оригинальных КИ (СТС) | PR → PO → оплата → поставка → склад |
| 15 | Выходной контроль | Отдел качества УПП | КИ на склад |
| 16 | Сборка прототипа | Бюро сборки, склад, мастер, рабочий, контролёр | Собранный прототип |
| 17 | Акт об изготовлении | Контролёр, технолог, мастер, начальник цеха | Подписанный акт |
| 18 | Передача заказчику | Логист УПП + представитель заказчика | Накладная + акт |
| 19 | Отчётность (раз в месяц) | прото-РП + экономист УПП | Проект + руководство |

### 8.2. Ключевые правила процесса

1. До ТЗ — ничего не запускается. Ни ТД, ни заявки на КИ, ни наряд-заказы.
2. Проработка и техпроверка — параллельно. Технологи проверяют те КИ, которые уже есть в составе.
3. Итерации проработки — не регламентированы.
4. ТЗ — триггер.
5. План валидации — основа бюджета.
6. Разрушающие испытания → утилизация.
7. Аутсорс — при техневозможности.
8. Серийное производство привлекается: решают прото-РП + технолог.

### 8.3. Параллельность

| Этап | Параллельно с | Причина |
|------|---------------|---------|
| Проработка состава | Технологическая проверка | Экономия времени |
| Технологическая проверка | Проработка состава | По мере поступления КИ |

| Параметр | Значение |

| Параметр | Значение |
|----------|----------|
| Назначение прототипа | Проведение испытаний |
| Результат испытаний | ок / не ок — не важен |
| Прототип выполняет предназначение | Всегда |
| Источник информации | О валидности КД |
| Название документа | План валидации = план работ по проверке соответствия КД заявленным требованиям |
| Суть | Проверка и валидация конструкторских решений |
| Разрушающие испытания | После — утилизация |
| Итеративность | КД → прототип → испытание → отчёт → доработка КД → новый прототип |
| Сертификация | Образец зрелой конструкции, прошедший внутренние проверки |

### Пример из практики (дословно)

> Изготовили ДВС, провели испытания.
> Оказалось: модуль впуска создаёт слишком большое сопротивление воздушному потоку.
> Спроектировали новый модуль впуска.
> Проект направляет особое задание в УПП — задание на ретрофит ДВС.
> Проект достигает целей без перерасхода ресурсов.
> Не нужно изготавливать новый ДВС.
> Заменили модуль впуска — объект (ДВС) приобрёл новые технические характеристики.
> Затем — снова испытания.

## ЧАСТЬ 21. МУЛ (MULE)

### 21.1. Определение

Мул — это гибрид серийного автомобиля-носителя и опытных КИ, созданный для ускорения процесса разработки нового автомобиля.

### 21.2. Когда применяется

Когда нужно провести длительные испытания уже спроектированных деталей, узлов и систем, а автомобиль ещё не спроектирован целиком и его нельзя изготовить целиком.

### 21.3. Как создаётся

1. Выбирают наиболее схожую с проектируемой моделью существующую серийную модель.
2. Проект выбирает модель. Окончательное решение — главный инженер.
3. Забирают автомобиль из серийного производства. Оформляется актом.
4. Себестоимость носителя учитывается в бюджете проекта через экономиста проекта.
5. Направляют в УПП запрос на переоборудование.
6. УПП переоборудует серийный автомобиль, устанавливая прототипные детали, узлы.
7. Кузов, как правило, тоже претерпевает изменения.
8. Получается гибрид (серийный автомобиль-носитель + опытные КИ) = мул.

### 21.4. Что дальше

- Мул передают в подразделение, занимающееся испытаниями.
- После испытаний — утилизация.
- Опытные КИ — утилизация.

### 21.5. Документы

| Документ | Значение |
|----------|----------|
| Передача носителя из серийного производства | Акт |
| Запрос на переоборудование | ТЗ |
| Акт на переоборудование | Так же, как при ретрофите |

### 21.6. Ограничения

| Параметр | Значение |
|----------|----------|
| Ограничения по количеству | Нет |
| С точки зрения бюджета | Чем меньше, тем лучше |
| На практике | От 4 до 10 |
| Место в проекте | Первый лот. Почти всегда |
| Связь с планом валидации | Обязательно фигурирует |

### 21.7. Названия процесса

| Название | Статус |
|----------|--------|
| «Переоборудование серийного автомобиля» | Обычное |
| «Изготовление мула» | Обычное |
| «Ретрофит» | Изредка. Не совсем верно |

### 21.8. Отличие от ретрофита

| Критерий | Мул (MULE) | Ретрофит (Retrofit) |
|----------|------------|---------------------|
| Что переоборудуется | Серийный автомобиль-носитель | Автомобиль/мул, ранее изготовленный в УПП |
| История объекта | Новый серийный автомобиль | Уже прошёл хотя бы раз испытания |
| Источник | Серийное производство | Испытания / калибровки |
| Кузов | Как правило, тоже претерпевает изменения | — |
| Документ | ТЗ | ТЗ |
| Акт | Так же, как при ретрофите | Акт приёма-передачи |
| Что дальше | Испытания | Испытания |
