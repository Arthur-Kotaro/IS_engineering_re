# Глоссарий ERP «Engineering:re»

## Организационная структура

| Термин | Определение |
|---|---|
| **Служба (Division)** | Уровень 1 иерархии. СГТ, СТС. |
| **Дирекция (Directorate)** | Уровень 2. ДИП, PMD, ДПЗ, ДИС. |
| **Управление (Department)** | Уровень 3. УПП. |
| **Отдел (Section)** | Уровень 4. КТО, экономисты, планирование, логистика, качество. |
| **Цех (Shop)** | Уровень 4. Цех 1, Цех 2. |
| **Бюро (Bureau)** | Уровень 5. Есть начальник. |
| **Группа (Group)** | Уровень 5. Нет начальника, подчиняется начальнику отдела. |
| **Производственный участок (Area)** | Уровень 5. |
| **Кладовая (Store)** | Уровень 5. Tool Store. |
| **Подразделение** | Любой элемент иерархии. |
| **Мастер** | Должность, не подразделение. |

## Пользователи, должности, роли

| Термин | Определение |
|---|---|
| **Пользователь** | Учётная запись в User Service. Всегда имеет должность и хотя бы одну роль. |
| **Должность (Position)** | Обобщённая должность из справочника `positions`. Одна на пользователя. Например: `director`, `section_head`, `engineer`. |
| **Разрешённая роль (Role)** | Роль из справочника `roles`, назначенная пользователю. Определяет функционал и права в системе. Может быть несколько. |
| **Проектная роль (Project Role)** | Роль пользователя в конкретном проекте. Из справочника `project_roles` в Project Service. |
| **Роль = производная (position, dept)** | Один и тот же `section_head` в разных отделах = разные роли (`kto_head`, `econ_head`, ...). |

## Проект

| Термин | Определение |
|---|---|
| **Проект** | Единица планирования. Хранится в Project Service. |
| **Команда проекта** | Набор пользователей с проектными ролями. |
| **Главный инженер (CVE)** | Глава проекта. Утверждает команду. Ведёт 1–2 проекта. |
| **Инженер по планированию продукта (IPP)** | Держатель мастерграфика. Формирует команду. |
| **Прото-РП** | Руководитель проекта по прототипам. Сквозной координатор. |
| **Проектная роль `project_member`** | Плейсхолдер для неспециализированных участников. Минимальные права. |
| **Периметр** | Зона ответственности члена команды за задачу МГ. |

## Доступ и права

| Термин | Определение |
|---|---|
| **Право (permission)** | Разрешение на действие. |
| **`view_project`** | Просмотр проекта. Все члены команды. |
| **`edit_mastergraphic`** | Редактирование МГ. CVE и IPP проекта. |
| **`manage_members`** | Управление командой. CVE и IPP. |
| **`approve_members`** | Утверждение команды. CVE. |
| **`edit_project`** | Редактирование метаданных проекта. CVE. |
| **`delete_project`** | Удаление проекта. Не реализовано. |

## Имперсонация

| Термин | Определение |
|---|---|
| **Имперсонация** | Действие от имени другого пользователя. |
| **Обратное делегирование** | Начальник → подчинённый. Не требует акта. Не хранится. |
| **Прямое делегирование** | Начальник → подчинённый. Свои полномочия. Хранится. |
| **Временное делегирование** | Начальник передаёт полномочия подчинённого А подчинённому Б. |
| **«Войти как …»** | Плитка Navigation Service. |

## Плитки

| Термин | Определение |
|---|---|
| **Плитка (Tile)** | Элемент рабочего стола. Ведёт на endpoint. |
| **Плитки по роли** | Привязаны к разрешённой роли. |
| **Плитки по должности** | Привязаны к должности. |
| **Универсальные плитки** | Для всех: `profile`, `impersonate`. |
| **`admin` получает все плитки** | Специальный случай. |

## Инфраструктура

| Термин | Определение |
|---|---|
| **X-User-ID** | Идентификатор пользователя. Ставит nginx. |
| **X-User-Role** | Разрешённые роли через запятую, либо `super_admin`. |
| **X-User-Position** | Должность (одна). |
| **X-Impersonated-By** | Реальный действующий при имперсонации. |
| **X-Internal-Key** | Для `/internal/*`. |
| **Blacklist** | Redis DB 0. Отозванные JWT. |
| **Имперсонация-сессия** | Redis DB 0. `impersonation:{uuid}`. |
