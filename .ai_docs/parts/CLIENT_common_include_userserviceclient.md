# Часть: CLIENT/common/include/userserviceclient

## Назначение этой части

Эта часть проекта содержит заголовочные файлы, которые определяют классы и структуры для взаимодействия с пользовательскими сервисами в ERP-системе. Эти компоненты отвечают за управление аутентификацией, авторизацией, токенами доступа и данными пользователей.

## Основные компоненты и их ответственность

1. **ApiClient.h**
   - Класс `ApiClient` предоставляет базовые методы для выполнения HTTP-запросов к серверу.
   - Методы: `get`, `post`, `put`, `del` для различных типов запросов.
   - Свойства: управление URL-адресом сервера, токенами аутентификации и статусом подключения.

2. **AuthService.h**
   - Класс `AuthService` отвечает за аутентификацию пользователей, обновление токенов доступа, смену паролей и управление сессией пользователя.
   - Методы: `login`, `refreshToken`, `logout`, `changePassword`, `resetPassword`, `checkPasswordExpiry`, `fetchUserProfile`, `fetchUserStatus`.
   - Структуры: `LoginResponse`, `UserSession`, `AuthResult` для представления результатов аутентификации и сессии пользователя.

3. **TokenManager.h**
   - Класс `TokenManager` управляет токенами доступа и обновления.
   - Методы: `setTokens`, `clearTokens`, `updateRefreshToken`.
   - Свойства: хранение токенов доступа и обновления, проверка их валидности.

4. **UserDataModels.h**
   - Структуры данных для представления информации о пользователях и проектах.
   - Структуры: `ProjectRole`, `UserInfo` с методами сериализации/десериализации в JSON.

5. **UserProfile.h**
   - Структура `UserProfile` содержит подробную информацию о пользователе, включая его статус и роли.
   - Методы: `toJson`, `fromJson` для работы с JSON-представлением профиля пользователя.
   - Вспомогательные методы: проверка активности пользователя, наличие ролей.

6. **UsersServiceClient_global.h**
   - Макросы и определения для экспорта/импорта символов библиотеки `UsersServiceClient`.

## Ключевые сущности

- **ApiClient**: класс для выполнения HTTP-запросов к серверу.
- **AuthService**: класс для управления аутентификацией и авторизацией пользователей.
- **TokenManager**: класс для управления токенами доступа.
- **ProjectRole**: структура данных для представления ролей пользователя в проектах.
- **UserInfo**: структура данных для представления информации о пользователе.
- **UserProfile**: структура данных для представления подробной информации о пользователе.

## API эндпоинты

API эндпоинты не определены непосредственно в заголовочных файлах этой части проекта. Однако, классы `ApiClient` и `AuthService` предполагают взаимодействие с следующими эндпоинтами:

- `/login`: для аутентификации пользователя.
- `/refresh_token`: для обновления токена доступа.
- `/logout`: для выхода из системы.
- `/change_password`: для изменения пароля пользователя.
- `/reset_password`: для сброса пароля пользователя.
- `/user/profile`: для получения профиля пользователя.
- `/user/status`: для получения статуса пользователя.

## Зависимости от других частей

Эта часть проекта зависит от следующих компонентов:

- **Qt**: используется для создания объектно-ориентированного интерфейса и выполнения сетевых запросов.
- **QNetworkAccessManager**: класс Qt для выполнения HTTP-запросов.
- **QJsonDocument, QJsonObject**: классы Qt для работы с JSON-данными.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительские компоненты**:
  - `CLIENT/common/include`: общая директория для заголовочных файлов клиента.
  
- **Дочерние компоненты**:
  - Классы и структуры, определенные в этой части проекта, используются другими частями клиентского приложения для взаимодействия с пользовательскими сервисами.

Эта часть проекта является фундаментальной для обеспечения аутентификации, авторизации и управления данными пользователями в ERP-системе.
