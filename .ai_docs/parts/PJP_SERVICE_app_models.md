# PJP_SERVICE/app/models

## Назначение этой части

Модуль `PJP_SERVICE/app/models` отвечает за определение структуры данных, используемых в сервисе управления Проектными Жизненными Планами (PJP). Он содержит модели базы данных, которые представляют сущности PJP, черновики PJP и документы PDM. Эти модели используются для взаимодействия с PostgreSQL через SQLAlchemy ORM.

## Основные компоненты и их ответственность

1. **draft.py**
   - Содержит модели `PJPDraft` и `PJPDraftPart`, которые представляют черновики PJP и части этих черновиков соответственно.
   
2. **pdm.py**
   - Содержит модель `PDMDocument`, которая представляет документы PDM (Product Data Management).

3. **pjp.py**
   - Содержит модели `PJP`, `PJPPart` и `PJPChangeLog`. Модель `PJP` представляет основные данные о Проектном Жизненном Плане, модель `PJPPart` — детали частей PJP, а модель `PJPChangeLog` — записи изменений в PJP.

## Ключевые сущности

1. **PJPDraft**
   - Основная информация о черновике PJP.
   - Связана с `PJPDraftPart`.

2. **PJPDraftPart**
   - Детали частей для черновика PJP.
   - Связана с `PJPDraft` через отношение "один ко многим".

3. **PDMDocument**
   - Информация о документах PDM, связанных с проектами.

4. **PJP**
   - Основная информация о Проектном Жизненном Плане.
   - Связана с `PJPPart` и `PJPChangeLog`.

5. **PJPPart**
   - Детали частей для PJP.
   - Связана с `PJP` через отношение "один ко многим".
   - Может иметь родительские и дочерние части.

6. **PJPChangeLog**
   - Записи изменений в Проектном Жизненном Плане.
   - Связана с `PJP`.

## API эндпоинты

В данном модуле нет определения API эндпоинтов, так как он предназначен для описания структуры данных. Однако, эти модели используются в контроллерах и маршрутах FastAPI для взаимодействия с базой данных.

## Зависимости от других частей

- **app.database**: Используется для подключения к базе данных PostgreSQL.
- **enum**: Для определения перечислимых типов (например, `PJPStatus`, `PartLineStatus` и `SourceType`).
- **sqlalchemy**: Для работы с ORM.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительские компоненты**:
  - Модуль `app.database` предоставляет базовые классы и функциональность для взаимодействия с базой данных.
  
- **Дочерние компоненты**:
  - Контроллеры и маршруты FastAPI используют эти модели для выполнения операций CRUD (создание, чтение, обновление, удаление) над данными.

Этот модуль является ключевым в обеспечении правильной структуры данных и взаимодействия с базой данных в сервисе управления Проектными Жизненными Планами.
