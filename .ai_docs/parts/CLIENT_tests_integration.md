# CLIENT/tests/integration

## Назначение этой части

Компонент `CLIENT/tests/integration` предназначен для интеграционного тестирования клиентской части ERP-системы для инжиниринговых компаний. Интеграционные тесты проверяют взаимодействие различных модулей и компонентов клиента с внешними сервисами, такими как API Gateway и микросервисы (например, USER_service).

## Основные компоненты и их ответственность

1. **TestApiClient.cpp**
   - **Ответственность:** Тестирует функциональность класса `ApiClient`, который отвечает за взаимодействие с API Gateway и другими микросервисами.
   
2. **TestAuthService.cpp**
   - **Ответственность:** Тестирует функциональность классов, связанных с аутентификацией и авторизацией пользователей, такие как `ProjectRole` и `UserInfo`. Проверяет сериализацию и десериализацию данных в формате JSON.
   
3. **TestMastergraphService.cpp**
   - **Ответственность:** Тестирует функциональность сервиса Mastergraph (возможно, отвечающего за графические представления или диаграммы проектов).

## Ключевые сущности

1. **ProjectRole**
   - Представляет роль пользователя в конкретном проекте.
   
2. **UserInfo**
   - Содержит информацию о пользователе, такую как идентификатор, email, полное имя, должность и список ролей в различных проектах.

## API эндпоинты (если есть)

В текущем компоненте нет явного определения API эндпоинтов. Однако, тесты предполагают взаимодействие с API Gateway и микросервисами через класс `ApiClient`. Предположительно, следующие эндпоинты могут быть использованы:

1. **/api/user/project-roles**
   - Получение и обновление ролей пользователя в проектах.
   
2. **/api/user/info**
   - Получение информации о пользователе.

## Зависимости от других частей (если известны)

1. **CLIENT/common/userserviceclient/UserDataModels.h**
   - Содержит определения классов `ProjectRole` и `UserInfo`, используемых в тестах.
   
2. **API_Gateway**
   - Предполагается, что через API Gateway происходят запросы к микросервисам для получения и обновления данных пользователей.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский компонент:** `CLIENT/tests`
  - Компонент `integration` является подкомпонентом тестов клиента, который фокусируется на интеграционных тестах.
  
- **Дочерние компоненты:**
  - В текущей структуре нет дочерних компонентов. Все необходимые файлы находятся непосредственно в директории `integration`.
