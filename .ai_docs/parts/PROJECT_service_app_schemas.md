# PROJECT_service/app/schemas

## Назначение этой части

Компонент `PROJECT_service/app/schemas` отвечает за определение структур данных, используемых для валидации и сериализации запросов и ответов API сервиса управления проектами. Эти схемы обеспечивают согласованность данных между клиентской частью ERP системы и серверной частью, а также упрощают процесс обработки и передачи информации.

## Основные компоненты и их ответственность

1. **`__init__.py`**: Пустой файл, который делает директорию `schemas` пакетом Python.
2. **`project.py`**: Содержит определения схем данных для различных операций над проектами.

## Ключевые сущности

- **ProjectCreate**: Схема для создания нового проекта.
- **ProjectUpdate**: Схема для обновления существующего проекта.
- **ProjectStatusUpdate**: Схема для изменения статуса проекта.
- **ProjectResponse**: Схема ответа, возвращаемая при запросе информации о проекте.
- **ProjectDetailResponse**: Расширенная схема ответа, содержащая подробную информацию о проекте и его участниках.
- **ProjectMemberCreate**: Схема для добавления нового участника в проект.
- **ProjectMemberResponse**: Схема ответа, возвращаемая при запросе информации о участнике проекта.
- **CheckAccessResponse**: Схема ответа, возвращаемая при проверке доступа пользователя к проекту.

## API эндпоинты (если есть)

В данном компоненте нет определения API эндпоинтов. Однако, схемы данных используются следующими эндпоинтами:

- **POST /projects/**: Создание нового проекта.
- **PUT /projects/{project_id}**: Обновление существующего проекта.
- **PATCH /projects/{project_id}/status**: Изменение статуса проекта.
- **GET /projects/{project_id}**: Получение информации о проекте.
- **GET /projects/{project_id}/details**: Получение подробной информации о проекте и его участниках.
- **POST /projects/{project_id}/members/**: Добавление нового участника в проект.
- **GET /projects/{project_id}/members/{user_id}**: Получение информации о участнике проекта.
- **GET /projects/{project_id}/access/check**: Проверка доступа пользователя к проекту.

## Зависимости от других частей (если известны)

- **`app.models.project.ProjectStatus`**: Используется для определения статусов проекта.
- **FastAPI**: Для валидации и сериализации данных запросов и ответов.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительские компоненты**:
  - `PROJECT_service/app`: Основной пакет сервиса управления проектами, который использует определенные здесь схемы данных для обработки запросов и формирования ответов.
  
- **Дочерние компоненты**:
  - Отсутствуют непосредственные дочерние компоненты, так как `schemas` является конечным узлом в данной иерархии.

Этот компонент играет ключевую роль в обеспечении корректности данных, передаваемых между клиентской частью ERP системы и серверной частью, а также в поддержании согласованности интерфейсов API.
