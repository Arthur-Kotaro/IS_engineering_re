# Проектная часть: PROJECT_service/app

## Назначение этой части

Модуль `PROJECT_service/app` является ключевым компонентом сервиса управления проектами в ERP для инжиниринговых компаний. Он предоставляет функциональность для создания, обновления, удаления и просмотра проектов, а также управления участниками этих проектов.

## Основные компоненты и их ответственность

1. **API**
   - `api/v1/projects.py`: Определяет маршруты API для работы с проектами.
   
2. **Модели**
   - `models/project.py`: Определяет модель данных `Project` для хранения информации о проектах.
   - `models/project_member.py`: Определяет модель данных `ProjectMember` для управления участниками проектов.

3. **Репозитории**
   - `repositories/project_repo.py`: Содержит методы для взаимодействия с базой данных, такие как создание, получение, обновление и удаление проектов и участников проектов.
   
4. **Схемы**
   - `schemas/project.py`: Определяет схемы Pydantic для валидации входных и выходных данных API.

5. **Сервисы**
   - `services/project_service.py`: Содержит бизнес-логику, используя репозитории для выполнения операций над проектами и участниками проектов.
   
6. **Утилиты**
   - `utils/__init__.py`: Пока что пустой файл, но может быть расширен в будущем.

7. **Конфигурация**
   - `config.py`: Определяет настройки приложения, такие как URL базы данных и другие параметры.
   
8. **База данных**
   - `database.py`: Инициализирует подключение к базе данных и предоставляет сессии для работы с ней.

9. **Зависимости**
   - `dependencies.py`: Определяет зависимости, такие как проверка токена пользователя и проверка ролей.

10. **Основной файл приложения**
    - `main.py`: Инициализирует FastAPI приложение и подключает маршруты API.

## Ключевые сущности

1. **Project**: Представляет проект в системе, содержит информацию о названии, описании, статусе, создателе и датах создания/обновления.
2. **ProjectMember**: Представляет участника проекта, связывает пользователя с проектом и указывает его роль.

## API эндпоинты

1. **Получение списка проектов**
   - `GET /api/v1/projects`
   
2. **Создание нового проекта**
   - `POST /api/v1/projects`
   
3. **Получение информации о конкретном проекте**
   - `GET /api/v1/projects/{project_id}`
   
4. **Обновление информации о проекте**
   - `PUT /api/v1/projects/{project_id}`
   
5. **Изменение статуса проекта**
   - `PATCH /api/v1/projects/{project_id}/status`
   
6. **Удаление проекта**
   - `DELETE /api/v1/projects/{project_id}`
   
7. **Добавление участника в проект**
   - `POST /api/v1/projects/{project_id}/members`
   
8. **Удаление участника из проекта**
   - `DELETE /api/v1/projects/{project_id}/members/{user_id}`
   
9. **Проверка доступа пользователя к проекту**
   - `GET /api/v1/projects/{project_id}/check-access`

## Зависимости от других частей

- **USER_service**: Используется для проверки токена и ролей пользователей.
- **База данных PostgreSQL**: Хранит данные о проектах и участниках проектов.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский компонент**: `PROJECT_service` - модуль `app` является частью сервиса управления проектами.
- **Дочерние компоненты**:
  - Маршруты API определены в `api/v1/projects.py`.
  - Модели данных определены в `models/project.py` и `models/project_member.py`.
  - Репозитории для работы с базой данных определены в `repositories/project_repo.py`.
  - Схемы Pydantic для валидации данных определены в `schemas/project.py`.
  - Сервисы бизнес-логики определены в `services/project_service.py`.
