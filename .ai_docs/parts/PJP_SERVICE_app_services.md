# PJP_SERVICE/app/services

## Назначение этой части

Компонент `PJP_SERVICE/app/services` отвечает за бизнес-логику по управлению черновиками (drafts) и окончательными документами (PJP - Project Job Plan). Он включает сервисы для создания, обновления, удаления и публикации черновиков, а также валидацию данных перед их сохранением.

## Основные компоненты и их ответственность

1. **draft_services.py**
   - **DraftService**: Класс, предоставляющий методы для работы с черновиками (drafts). Включает создание, получение, добавление частей, обновление частей, удаление частей, очистку черновика и получение списка частей черновика.

2. **pjp_service.py**
   - **PJPService**: Класс, предоставляющий методы для работы с окончательными документами (PJP). Включает публикацию черновика в PJP, конвертацию количества из строки в Decimal и получение PJP по его ID.

3. **validator.py**
   - Модуль содержит функции для валидации данных частей черновика перед их публикацией в PJP. Включает `validate_part` для проверки одной части и `validate_pjp` для проверки всего PJP.

## Ключевые сущности

1. **PJPDraft**: Модель базы данных, представляющая черновик проекта.
2. **PJPDraftPart**: Модель базы данных, представляющая часть черновика.
3. **PJP**: Модель базы данных, представляющая окончательный документ (Project Job Plan).
4. **PJPPart**: Модель базы данных, представляющая часть окончательного документа.

## API эндпоинты

В данном компоненте нет прямых API эндпоинтов. Он предоставляет сервисные методы, которые могут быть вызваны из контроллеров или других частей приложения для выполнения бизнес-логики.

## Зависимости от других частей

1. **app.models**: Модели базы данных.
2. **app.schemas**: Схемы данных для валидации и сериализации.
3. **sqlalchemy.ext.asyncio.AsyncSession**: Асинхронная сессия SQLAlchemy для взаимодействия с базой данных.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительские компоненты**:
  - Контроллеры (например, `PJP_SERVICE/app/controllers`), которые вызывают методы сервисов для выполнения бизнес-логики.
  
- **Дочерние компоненты**:
  - Модели базы данных (`app.models`) и схемы данных (`app.schemas`), которые используются для работы с данными.

Этот компонент является центральным в управлении черновиками и окончательными документами, обеспечивая корректное выполнение бизнес-логики и валидацию данных.
