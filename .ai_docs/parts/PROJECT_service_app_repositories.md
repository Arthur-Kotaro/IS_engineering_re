# PROJECT_service/app/repositories

## Назначение этой части

Компонент `PROJECT_service/app/repositories` отвечает за управление доступом к данным проектов и их участникам в базе данных. Он предоставляет асинхронные методы для создания, чтения, обновления и удаления (CRUD) проектов, а также управления участниками этих проектов.

## Основные компоненты и их ответственность

### `__init__.py`
- **Назначение**: Инициализация пакета. В данном случае файл пустой, что указывает на то, что основная логика находится в других файлах.

### `project_repo.py`
- **Класс `ProjectRepository`**:
  - **Методы**:
    - `create`: Создает новый проект.
    - `get_by_id`: Получает проект по идентификатору.
    - `get_all`: Получает список всех проектов с возможностью фильтрации по статусу, пагинацией.
    - `update`: Обновляет информацию о проекте.
    - `delete`: Удаляет проект.
    - `add_member`: Добавляет участника в проект.
    - `remove_member`: Удаляет участника из проекта.
    - `get_member`: Получает информацию о участнике проекта.
    - `get_user_projects`: Получает список всех проектов, в которых участвует пользователь.

## Ключевые сущности

- **Project**: Проект инжиниринговой компании.
- **ProjectMember**: Участник проекта (например, инженер, менеджер).

## API эндпоинты

В данном компоненте нет прямых API эндпоинтов. Он предоставляет методы для взаимодействия с базой данных, которые могут быть вызваны из сервисных слоев или контроллеров.

## Зависимости от других частей

- **`app.models.project`**: Модели данных проектов.
- **`app.models.project_member`**: Модели данных участников проектов.
- **SQLAlchemy**: ORM для взаимодействия с базой данных PostgreSQL.

## Взаимодействие с родительскими/дочерними компонентами

### Родительские компоненты
- **`PROJECT_service/app/services`**: Сервисные слои, которые используют репозиторий для выполнения бизнес-логики.
- **`PROJECT_service/app/controllers`**: Контроллеры, которые вызывают сервисные слои и обрабатывают запросы от API Gateway.

### Дочерние компоненты
- Нет прямых дочерних компонентов. Все взаимодействие происходит через методы класса `ProjectRepository`.
