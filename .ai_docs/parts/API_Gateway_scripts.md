# API Gateway Scripts

## Назначение этой части

Модуль `API_Gateway/scripts` содержит скрипты для управления жизненным циклом API-шлюза, включая запуск, остановку и просмотр логов. Эти скрипты упрощают процесс развертывания и отладки API-шлюза в контейнеризированной среде Docker.

## Основные компоненты и их ответственность

1. **logs.sh**
   - **Ответственность:** Отображает последние 100 строк логов API-шлюза в реальном времени.
   
2. **start.sh**
   - **Ответственность:** Запускает API-шлюз в фоновом режиме с пересборкой контейнеров при необходимости и выводит информацию о доступных маршрутах.

3. **stop.sh**
   - **Ответственность:** Останавливает работу API-шлюза, освобождая используемые ресурсы.

## Ключевые сущности

1. **Docker Compose** — инструмент для управления многоконтейнерными приложениями Docker.
2. **Nginx** — веб-сервер и обратный прокси, используемый как API-шлюз.

## API эндпоинты

API-шлюз перенаправляет запросы на соответствующие микросервисы по следующим маршрутам:

1. **`http://localhost:8080/api/v1/auth/login`** — аутентификация пользователя (User Service).
2. **`http://localhost:8080/api/v1/users/me`** — получение информации о текущем пользователе (User Service).
3. **`http://localhost:8080/api/v1/projects/`** — управление проектами (Project Service).
4. **`http://localhost:8080/health`** — проверка состояния API-шлюза.

## Зависимости от других частей

1. **API_Gateway/docker-compose.yml** — файл конфигурации Docker Compose, который определяет сервисы и их зависимости.
2. **API_Gateway/nginx/** — конфигурационные файлы Nginx для настройки маршрутизации запросов.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительские компоненты:**
  - **API_Gateway/** — основной каталог API-шлюза, содержащий конфигурационные файлы и скрипты.
  
- **Дочерние компоненты:**
  - **logs.sh**, **start.sh**, **stop.sh** — скрипты для управления API-шлюзом.

Эти скрипты взаимодействуют с родительскими компонентами через файл `docker-compose.yml`, который описывает конфигурацию и зависимости сервисов. Они также используются в других скриптах проекта, таких как `start_all.sh` и `stop_all.sh`, для управления всеми микросервисами системы ERP.
