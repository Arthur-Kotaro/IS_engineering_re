# PJP_SERVICE/app/api

## Назначение этой части

Компонент `PJP_SERVICE/app/api` является частью бэкенда ERP системы для инжиниринговых компаний, реализованного на Python с использованием фреймворка FastAPI. Он предоставляет API для работы с Проектными Жизненными Планами (PJP), черновиками и документами технической документации (КД).

## Основные компоненты и их ответственность

1. **draft.py**:
   - Обрабатывает запросы, связанные с созданием, получением, обновлением и удалением черновиков проектных планов.
   
2. **pdm.py**:
   - Обрабатывает запросы для получения и загрузки технической документации (КД) по референсному номеру.

3. **pjp.py**:
   - Обрабатывает запросы, связанные с получением, обновлением статуса и частей Проектных Жизненных Планов (PJP).

4. **__init__.py**:
   - Инициализирует модуль `v1` и экспортирует основные подмодули (`pjp`, `draft`, `pdm`), делая их доступными для импорта из других частей системы.

## Ключевые сущности

1. **Черновик (Draft)**:
   - Представляет собой промежуточное состояние Проектного Жизненного Плана, который еще не был опубликован.
   
2. **Проектный Жизненный План (PJP)**:
   - Окончательная версия черновика после проверки и публикации.

3. **Часть (Part)**:
   - Компоненты или элементы, входящие в состав Проектного Жизненного Плана или черновика.

4. **Документ технической документации (КД)**:
   - Файлы с техническими спецификациями и данными, используемыми в проекте.

## API эндпоинты

### Drafts
- **POST /drafts**:
  - Создает новый черновик.
  
- **GET /drafts**:
  - Получает все черновики пользователя.
  
- **GET /drafts/{draft_id}**:
  - Получает конкретный черновик по его ID.
  
- **POST /drafts/{draft_id}/parts**:
  - Добавляет часть в черновик.
  
- **PUT /drafts/{draft_id}/parts/{part_id}**:
  - Обновляет часть в черновике.
  
- **DELETE /drafts/{draft_id}/parts/{part_id}**:
  - Удаляет часть из черновика.
  
- **DELETE /drafts/{draft_id}/clear**:
  - Очищает все части черновика.
  
- **POST /drafts/{draft_id}/publish**:
  - Публикует черновик, создавая PJP.

### PDMDocuments
- **GET /documents/{reference_number}**:
  - Получает документ технической документации по референсному номеру.
  
- **POST /documents**:
  - Загружает новый документ технической документации (только для пользователей с ролями PFE/IST).

### PJPs
- **GET /{pjp_id}**:
  - Получает конкретный Проектный Жизненный План по его ID.
  
- **PATCH /{pjp_id}/status**:
  - Обновляет статус Проектного Жизненного Плана.
  
- **GET /{pjp_id}/parts**:
  - Получает части Проектного Жизненного Плана с возможной фильтрацией по GFE и типу источника.
  
- **GET /{pjp_id}/history**:
  - Получает историю изменений Проектного Жизненного Плана.

## Зависимости от других частей

1. **app.database**: 
   - Используется для взаимодействия с базой данных PostgreSQL.
   
2. **app.schemas**:
   - Содержит схемы данных, используемые в запросах и ответах API.
   
3. **app.services**:
   - Предоставляет бизнес-логику для обработки черновиков, PJP и КД.

## Взаимодействие с родительскими/дочерними компонентами

1. **Родительские компоненты**:
   - **PJP_SERVICE/app**: 
     - Содержит основные настройки и маршрутизацию для API.
   
2. **Дочерние компоненты**:
   - **draft.py**, **pdm.py**, **pjp.py**:
     - Обрабатывают конкретные запросы, связанные с черновиками, КД и PJP соответственно.

3. **Внешние сервисы**:
   - **USER_service**: 
     - Используется для получения ролей пользователя при загрузке документа технической документации (КД).

Этот компонент является ключевым в обеспечении функциональности системы управления Проектными Жизненными Планами и связанными с ними данными.
