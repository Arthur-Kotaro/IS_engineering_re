# PROJECT_service/app/api

## Назначение этой части

Компонент `PROJECT_service/app/api` отвечает за предоставление RESTful API для управления проектами в ERP-системе инжиниринговых компаний. Этот компонент позволяет клиентам взаимодействовать с данными о проектах, пользователях и их ролях в этих проектах.

## Основные компоненты и их ответственность

1. **`__init__.py`**: Инициализационный файл для пакета `api`, который может содержать импорты необходимых модулей или функций.
2. **`v1/__init__.py`**: Инициализационный файл для версии API v1, который также может содержать импорты необходимых модулей или функций.
3. **`v1/projects.py`**: Основной файл с определениями эндпоинтов API для управления проектами.

## Ключевые сущности

- **Проект (Project)**: Содержит информацию о проекте, такую как название, описание, статус и дата создания.
- **Пользователь (User)**: Пользователи системы, которые могут быть участниками проектов.
- **Роль пользователя в проекте (Role)**: Определяет права доступа пользователей к различным функциям и данным внутри проекта.

## API эндпоинты

### Получение списка проектов
**GET /api/v1/projects**
- **Параметры запроса**: 
  - `skip` (опционально): Смещение для постраничной навигации.
  - `limit` (опционально): Ограничение количества возвращаемых проектов.
  - `status` (опционально): Фильтр по статусу проекта.
  - `user_id` (опционально): ID пользователя для фильтрации проектов, в которых он участвует.
- **Ответ**: Список объектов `ProjectResponse`.

### Создание нового проекта
**POST /api/v1/projects**
- **Параметры запроса**: 
  - `data`: Объект `ProjectCreate` с данными о новом проекте.
  - `created_by`: ID пользователя, создавшего проект.
- **Ответ**: Объект `ProjectResponse`.

### Получение информации о конкретном проекте
**GET /api/v1/projects/{project_id}**
- **Параметры запроса**: 
  - `project_id`: ID проекта.
- **Ответ**: Объект `ProjectDetailResponse`.

### Обновление информации о проекте
**PUT /api/v1/projects/{project_id}**
- **Параметры запроса**: 
  - `project_id`: ID проекта.
  - `data`: Объект `ProjectUpdate` с новыми данными для проекта.
- **Ответ**: Объект `ProjectResponse`.

### Обновление статуса проекта
**PATCH /api/v1/projects/{project_id}/status**
- **Параметры запроса**: 
  - `project_id`: ID проекта.
  - `data`: Объект `ProjectStatusUpdate` с новым статусом проекта.
- **Ответ**: Объект `ProjectResponse`.

### Удаление проекта
**DELETE /api/v1/projects/{project_id}**
- **Параметры запроса**: 
  - `project_id`: ID проекта.
- **Ответ**: Статус 204 No Content.

### Добавление участника в проект
**POST /api/v1/projects/{project_id}/members**
- **Параметры запроса**: 
  - `project_id`: ID проекта.
  - `data`: Объект `ProjectMemberCreate` с данными о новом участнике.
- **Ответ**: Объект `ProjectMemberResponse`.

### Удаление участника из проекта
**DELETE /api/v1/projects/{project_id}/members/{user_id}**
- **Параметры запроса**: 
  - `project_id`: ID проекта.
  - `user_id`: ID пользователя, которого нужно удалить из проекта.
- **Ответ**: Статус 204 No Content.

### Проверка доступа к проекту
**GET /api/v1/projects/{project_id}/check-access**
- **Параметры запроса**: 
  - `project_id`: ID проекта.
  - `user_id`: ID пользователя для проверки доступа.
- **Ответ**: Объект `CheckAccessResponse`.

## Зависимости от других частей

1. **`app/database.py`**: Для получения асинхронной сессии базы данных.
2. **`app/schemas/project.py`**: Определения моделей данных для запросов и ответов API.
3. **`app/services/project_service.py`**: Сервисный слой, содержащий бизнес-логику управления проектами.
4. **`app/models/project.py`**: Модели базы данных для хранения информации о проектах.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский компонент**: `PROJECT_service/app`
  - Входит в состав пакета `app`, который является основным модулем сервиса управления проектами.
- **Дочерние компоненты**:
  - `v1`: Версия API, которая содержит конкретные реализации эндпоинтов для версии v1.

Этот компонент взаимодействует с клиентскими приложениями через HTTP-запросы и поддерживает операции CRUD (Create, Read, Update, Delete) для управления проектами.
