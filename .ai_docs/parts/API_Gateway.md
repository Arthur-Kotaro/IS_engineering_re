# API Gateway

## Назначение этой части

API Gateway служит центральной точкой входа для всех запросов к микросервисам системы ERP для инжиниринговых компаний. Он управляет маршрутизацией запросов, балансировкой нагрузки и обеспечивает безопасность доступа к различным сервисам.

## Основные компоненты и их ответственность

1. **Nginx**: 
   - **nginx.conf**: Основной конфигурационный файл Nginx, который определяет параметры работы веб-сервера.
   - **gateway.conf**: Конфигурационный файл для API Gateway, содержащий маршрутизацию запросов и настройки логирования.

2. **Скрипты**:
   - **logs.sh**: Скрипт для просмотра логов API Gateway в реальном времени.
   - **start.sh**: Скрипт для запуска API Gateway с использованием Docker Compose.
   - **stop.sh**: Скрипт для остановки API Gateway.

3. **Dockerfile**:
   - Описывает процесс сборки Docker-образа для API Gateway, включая копирование конфигурационных файлов и настройку логирования.

4. **docker-compose.yml**:
   - Определяет сервисы, их порты, зависимости и параметры запуска для контейнеризации API Gateway.

## Ключевые сущности

- **Маршрутизация запросов**: API Gateway направляет входящие HTTP-запросы к соответствующим микросервисам на основе URL.
- **Балансировка нагрузки**: В будущем может быть расширена для поддержки балансировки нагрузки между несколькими экземплярами сервисов.
- **Логирование**: Сбор и хранение логов запросов для мониторинга работы системы.

## API эндпоинты

1. **/health**:
   - Метод: GET
   - Описание: Проверка здоровья API Gateway.
   - Ответ: "Gateway is healthy\n"

2. **/health/all**:
   - Метод: GET
   - Описание: Агрегированный проверочный эндпоинт для всех сервисов (в текущей реализации возвращает фиксированную строку).
   - Ответ: "All services are healthy\n"

3. **/api/v1/auth/**:
   - Методы: GET, POST, PUT, DELETE
   - Описание: Перенаправление запросов к User Service для аутентификации и авторизации пользователей.

4. **/api/v1/users/**:
   - Методы: GET, POST, PUT, DELETE
   - Описание: Перенаправление запросов к User Service для управления данными пользователей.

5. **/api/v1/admin/**:
   - Методы: GET, POST, PUT, DELETE
   - Описание: Перенаправление запросов к User Service для административных операций с пользователями.

6. **/api/v1/navigation/**:
   - Методы: GET, POST, PUT, DELETE
   - Описание: Перенаправление запросов к соответствующему сервису (в текущей реализации перенаправляется к User Service).

7. **/api/v1/projects/**:
   - Методы: GET, POST, PUT, DELETE
   - Описание: Перенаправление запросов к Project Service для управления проектами.

8. **/**
   - Метод: GET
   - Описание: Корневой эндпоинт API Gateway.
   - Ответ: "API Gateway is running\n"

## Зависимости от других частей

- **User Service**: Обрабатывает запросы, связанные с аутентификацией, авторизацией и управлением пользователями.
- **Project Service**: Обрабатывает запросы, связанные с управлением проектами.

## Взаимодействие с родительскими/дочерними компонентами

API Gateway взаимодействует с различными микросервисами системы ERP для инжиниринговых компаний. Он не имеет родительских компонентов, но является ключевым элементом управления трафиком между клиентскими приложениями и внутренними сервисами.

- **Клиентские приложения**: Отправляют запросы к API Gateway, который затем перенаправляет их к соответствующим микросервисам.
- **Микросервисы (User Service, Project Service)**: Получают запросы от API Gateway и выполняют необходимые операции.

API Gateway обеспечивает централизованное управление всеми входящими запросами, что упрощает масштабирование системы и поддержку безопасности.
