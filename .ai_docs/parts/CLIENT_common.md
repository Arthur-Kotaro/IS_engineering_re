# Часть: CLIENT/common

## Назначение этой части

Модуль `CLIENT/common` является центральным компонентом клиентской стороны ERP-системы для инжиниринговых компаний. Он предоставляет общий функционал для взаимодействия с серверной частью системы, включая аутентификацию пользователей, управление токенами доступа и получение информации о профилях пользователей.

## Основные компоненты и их ответственность

1. **ApiClient**:
   - Отвечает за выполнение HTTP-запросов к серверу.
   - Обрабатывает авторизацию через токены доступа.
   - Предоставляет методы для выполнения GET, POST, PUT и DELETE запросов.

2. **AuthService**:
   - Управляет процессом аутентификации пользователей.
   - Обновляет токены доступа при необходимости.
   - Получает информацию о профиле пользователя и проверяет срок действия пароля.

3. **TokenManager**:
   - Хранит и управляет токенами доступа (access token и refresh token).
   - Предоставляет методы для установки, очистки и обновления токенов.
   - Сериализует и десериализует токены в JSON формат.

4. **UserDataModels**:
   - Определяет структуры данных для хранения информации о пользователях и их ролях в проектах.
   - Предоставляет методы для сериализации и десериализации этих структур из JSON формата.

5. **UserProfile**:
   - Хранит информацию о пользователе, включая его основные данные, статус, роли и проекты.
   - Предоставляет методы для сериализации и десериализации данных профиля из JSON формата.
   - Определяет метод для получения пути к каталогу виджетов на основе ролей пользователя.

## Ключевые сущности

1. **ApiResponse**:
   - Структура, содержащая результат HTTP-запроса: статус успешности, код ответа, данные и сообщения об ошибках.

2. **LoginResponse**:
   - Структура, содержащая токены доступа после успешной аутентификации пользователя.

3. **UserSession**:
   - Структура, представляющая текущую сессию пользователя, включая токены и данные профиля.

4. **AuthResult**:
   - Структура, содержащая результат операций аутентификации: статус успешности, сообщения об ошибках и данные сессии.

5. **ProjectRole**:
   - Структура, представляющая роль пользователя в проекте, включая ID проекта, название проекта, роль и дату последнего изменения.

6. **UserInfo**:
   - Структура, содержащая основную информацию о пользователе: ID, email, полное имя, должность, срок действия пароля и роли в проектах.

7. **UserProfile**:
   - Структура, представляющая профиль пользователя, включая его основные данные, статус, роли и проекты.

## API эндпоинты

Модуль `CLIENT/common` использует следующие API эндпоинты для взаимодействия с серверной частью системы:

1. **/login**:
   - Метод: POST
   - Описание: Аутентификация пользователя по email и паролю.
   - Входные данные: JSON объект с полями `email` и `password`.
   - Выходные данные: JSON объект с токенами доступа.

2. **/refresh**:
   - Метод: POST
   - Описание: Обновление токена доступа по refresh token.
   - Входные данные: JSON объект с полем `refresh_token`.
   - Выходные данные: JSON объект с новыми токенами доступа.

3. **/users/me**:
   - Метод: GET
   - Описание: Получение информации о текущем пользователе.
   - Выходные данные: JSON объект с данными профиля пользователя.

4. **/users/me/password-expiry**:
   - Метод: GET
   - Описание: Проверка срока действия пароля текущего пользователя.
   - Выходные данные: JSON объект с информацией о сроке действия пароля.

## Зависимости от других частей

Модуль `CLIENT/common` зависит от следующих компонентов:

1. **Qt6**:
   - Используется для создания графического интерфейса и выполнения сетевых запросов.
   
2. **OpenSSL (опционально)**:
   - Используется для обеспечения безопасности SSL соединений на Unix-подобных системах.

## Взаимодействие с родительскими/дочерними компонентами

1. **Родительские компоненты**:
   - Модуль `CLIENT/common` является подмодулем и используется другими частями клиентской стороны системы, такими как `engineering_client`, для выполнения сетевых запросов и управления сессиями пользователей.

2. **Дочерние компоненты**:
   - Модуль `CLIENT/common` не имеет дочерних компонентов, но он использует вспомогательные файлы, такие как заголовочные файлы (`*.h`) и исходные файлы (`*.cpp`), для реализации своей функциональности.

3. **Взаимодействие**:
   - Модуль `CLIENT/common` предоставляет интерфейсы для выполнения сетевых запросов, аутентификации пользователей и управления токенами доступа.
   - Другие части клиентской системы используют эти интерфейсы для взаимодействия с серверной частью ERP-системы.
