# Часть: CLIENT/scripts

## Назначение этой части

Модуль `CLIENT/scripts` содержит скрипты, необходимые для автоматизации различных задач в процессе разработки и тестирования клиентской части ERP-системы для инжиниринговых компаний. Эти скрипты обеспечивают удобство в развёртывании приложения на Linux, запуске мокового сервера для тестирования API User Service и выполнении тестов.

## Основные компоненты и их ответственность

1. **build_linux.sh**:
   - **Назначение**: Скрипт сборки проекта под операционную систему Linux.
   - **Ответственность**: Выполняет необходимые шаги для сборки бинарных файлов клиента, включая компиляцию исходного кода и создание пакета для развертывания.

2. **deploy_linux.sh**:
   - **Назначение**: Скрипт развёртывания клиентского приложения на Linux.
   - **Ответственность**: Копирует бинарные файлы, QML-файлы и конфигурационные файлы в директорию для развертывания. Также может упаковывать зависимости Qt для создания автономного приложения.

3. **mock_server.py**:
   - **Назначение**: Моковый HTTP сервер для тестирования API User Service.
   - **Ответственность**: Обрабатывает запросы к эндпоинтам, связанным с аутентификацией и состоянием пользователя, возвращая предопределённые JSON-ответы.

4. **run_tests.sh**:
   - **Назначение**: Скрипт запуска тестов для клиентского приложения.
   - **Ответственность**: Запускает все тесты с подробным выводом результатов и отдельно выполняет тесты библиотеки и инженерного клиента.

## Ключевые сущности

- **Бинарные файлы клиентского приложения** (`ProductionClient`, `EngineeringClient`).
- **QML-файлы**: Используются для создания пользовательского интерфейса на основе Qt/QML.
- **Конфигурационные файлы**: Настройки приложения, такие как параметры подключения к серверу и другие конфигурационные данные.

## API эндпоинты (если есть)

API эндпоинты реализованы в скрипте `mock_server.py`:

- **POST /api/v1/auth/login**:
  - **Описание**: Аутентификация пользователя по email и паролю.
  - **Параметры запроса**: JSON с полями `email` и `password`.
  - **Ответы**:
    - 200 OK: Возвращает токены доступа и обновления.
    - 401 Unauthorized: Неверные учетные данные.

- **POST /api/v1/auth/refresh**:
  - **Описание**: Обновление токена доступа.
  - **Ответы**:
    - 200 OK: Возвращает новые токены доступа и обновления.

- **GET /health**:
  - **Описание**: Проверка состояния сервера.
  - **Ответы**:
    - 200 OK: Возвращает JSON с текущим статусом и временем ответа.

- **GET /api/v1/auth/password-expiry**:
  - **Описание**: Получение информации о сроке действия пароля пользователя.
  - **Ответы**:
    - 200 OK: Возвращает информацию о количестве дней до истечения срока действия пароля.

## Зависимости от других частей (если известны)

- **CLIENT/common**: Содержит общие файлы и библиотеки, используемые клиентскими приложениями.
- **USER_service**: Моковый сервер (`mock_server.py`) имитирует API User Service для тестирования.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский модуль (CLIENT)**:
  - Скрипты в `CLIENT/scripts` используются для сборки, развертывания и тестирования приложений, находящихся в подкаталогах `production_client`, `engineering_client` и других.

- **Дочерние компоненты**:
  - Непосредственных дочерних компонентов нет. Скрипты взаимодействуют с файловой системой, внешними инструментами (например, `linuxdeployqt`) и сетевыми сервисами (моковый сервер).

Этот модуль обеспечивает автоматизацию процесса разработки и тестирования клиентского приложения ERP для инжиниринговых компаний.
