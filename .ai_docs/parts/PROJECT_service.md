# PROJECT_service

## Назначение части

**PROJECT_service** — это микросервис, предназначенный для управления проектами и проектными командами в ERP-системе для инжиниринговых компаний. Он предоставляет функциональность по созданию, обновлению, удалению и управлению участниками проектов.

## Основные компоненты и их ответственность

1. **app/api/v1/projects.py**:
   - Определяет маршруты API для управления проектами.
   - Обрабатывает запросы на создание, получение, обновление и удаление проектов.
   - Управляет участниками проекта (добавление/удаление).

2. **app/config.py**:
   - Конфигурационные параметры сервиса, такие как URL базы данных, размер пула соединений и т.д.

3. **app/database.py**:
   - Настройка подключения к базе данных PostgreSQL с использованием SQLAlchemy.
   - Создание асинхронного движка и сессии для взаимодействия с БД.

4. **app/dependencies.py**:
   - Зависимости для FastAPI, такие как проверка токена пользователя и управление ролями доступа.

5. **app/main.py**:
   - Основной файл приложения FastAPI.
   - Настройка жизненного цикла сервиса (запуск/остановка).
   - Подключение маршрутов API.

6. **app/models/project.py и app/models/project_member.py**:
   - Определение моделей данных для проектов и участников проектов.
   - Связи между таблицами в базе данных.

7. **app/repositories/project_repo.py**:
   - Репозиторий для взаимодействия с базой данных.
   - Методы для выполнения CRUD-операций над проектами и участниками проектов.

8. **app/schemas/project.py**:
   - Определение схем Pydantic для валидации входных и выходных данных API.

9. **app/services/project_service.py**:
   - Сервисный слой, содержащий бизнес-логику управления проектами.
   - Использует репозиторий для выполнения операций с базой данных.

## Ключевые сущности

1. **Project**:
   - Описывает проект в системе.
   - Содержит поля: `project_id`, `title`, `description`, `status`, `created_by`, `created_at`, `updated_at`.

2. **ProjectMember**:
   - Описывает участника проекта.
   - Содержит поля: `id`, `project_id`, `user_id`, `role`, `joined_at`.

## API эндпоинты

1. **GET /api/v1/projects/**
   - Получение списка проектов с возможностью фильтрации по статусу и пользователю.

2. **POST /api/v1/projects/**
   - Создание нового проекта.

3. **GET /api/v1/projects/{project_id}**
   - Получение подробной информации о проекте по его ID.

4. **PUT /api/v1/projects/{project_id}**
   - Обновление информации о проекте.

5. **PATCH /api/v1/projects/{project_id}/status**
   - Обновление статуса проекта.

6. **DELETE /api/v1/projects/{project_id}**
   - Удаление проекта по его ID.

7. **POST /api/v1/projects/{project_id}/members**
   - Добавление участника в проект.

8. **DELETE /api/v1/projects/{project_id}/members/{user_id}**
   - Удаление участника из проекта.

9. **GET /api/v1/projects/{project_id}/check-access**
   - Проверка доступа пользователя к проекту и его роли.

## Зависимости от других частей

- **USER_service**: Для проверки токена пользователя и получения информации о пользователе.
- **API_Gateway**: Для маршрутизации запросов к PROJECT_service.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительские компоненты**:
  - **API_Gateway**: Обрабатывает входящие запросы и перенаправляет их в PROJECT_service.
  
- **Дочерние компоненты**:
  - **USER_service**: Используется для проверки токена пользователя и получения информации о пользователе.

Этот микросервис является частью большей системы ERP, которая управляет различными аспектами деятельности инжиниринговой компании.
