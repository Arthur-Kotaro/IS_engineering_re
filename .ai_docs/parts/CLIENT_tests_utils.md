# CLIENT/tests/utils

## Назначение этой части

Компонент `CLIENT/tests/utils` предназначен для предоставления утилит и моков, используемых в модульных тестах клиента ERP системы. Эти утилиты помогают создавать макеты (mocks) API-клиента, генерировать тестовые данные и имитировать поведение сервера для проведения юнит-тестирования.

## Основные компоненты и их ответственность

1. **MockApiClient.cpp / MockApiClient.h**
   - **Описание:** Мок (макет) API клиента, который используется в тестах для имитации взаимодействия с сервером.
   - **Ответственность:**
     - Имитация методов `ApiClient` без реального сетевого взаимодействия.
     - Позволяет проверять логику клиента, не завися от доступности сервера.

2. **MockApiTestHelpers.h**
   - **Описание:** Вспомогательные функции и классы для тестирования API-клиента.
   - **Ответственность:**
     - Предоставление утилит для создания моков и тестовых данных, связанных с API.

3. **MockServer.h**
   - **Описание:** Интерфейс или базовый класс для имитации сервера в тестах.
   - **Ответственность:**
     - Определяет методы и структуры для создания мок-сервера, который может быть использован в тестах.

4. **TestHelpers.cpp / TestHelpers.h**
   - **Описание:** Вспомогательные функции для различных тестов.
   - **Ответственность:**
     - Генерация JWT токенов для аутентификации.
     - Создание тестовых payload пользователей и ответов сервера.

## Ключевые сущности

1. **MockApiClient** — мок API клиента, используемый в тестах.
2. **TestHelpers** — пространство имён с функциями для генерации тестовых данных (JWT токены, payload пользователей и ответов сервера).

## API эндпоинты

В данном компоненте нет прямых API эндпоинтов, так как он предназначен для тестирования. Однако макеты (`MockApiClient`) могут имитировать взаимодействие с следующими типичными эндпоинтами:
- `GET /api/users`
- `POST /api/auth/login`
- `PUT /api/projects/{id}`
- `DELETE /api/users/{id}`

## Зависимости от других частей

1. **CLIENT/common/include/userserviceclient/ApiClient.h**
   - **Ответственность:** Определение интерфейса API клиента, который имитируется в моках.

2. **gmock/gmock.h**
   - **Ответственность:** Библиотека для создания моков и тестовых заглушек.

3. **Qt (QString, QJsonObject, QJsonDocument, QByteArray)**
   - **Ответственность:** Используется для работы с JSON данными и строками в тестах.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский компонент: CLIENT/tests**
  - **Взаимодействие:** Компонент `CLIENT/tests/utils` является подкомпонентом модульных тестов клиента и предоставляет утилиты для их реализации.
  
- **Дочерние компоненты: Индивидуальные тестовые файлы**
  - **Взаимодействие:** Утилиты из `CLIENT/tests/utils` используются в конкретных тестовых файлах для создания моков и генерации тестовых данных.
