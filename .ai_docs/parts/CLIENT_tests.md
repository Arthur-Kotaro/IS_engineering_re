# Часть: CLIENT/tests

## Назначение этой части

Модуль `CLIENT/tests` предназначен для написания и выполнения тестов клиентской части ERP-системы для инжиниринговых компаний. Он включает в себя как юнит-тесты, так и интеграционные тесты, а также утилитарный код для поддержки этих тестов. Основная цель — обеспечить надежность и стабильность клиентского приложения путем автоматического тестирования различных его компонентов.

## Основные компоненты и их ответственность

1. **Тестовые утилиты**
   - `utils/MockApiClient.cpp` и `MockApiClient.h`: Мок-реализация API клиента для имитации взаимодействия с сервером.
   - `utils/TestHelpers.cpp` и `TestHelpers.h`: Вспомогательные функции для создания тестовых данных, таких как JWT токены и ответы сервера.

2. **Юнит-тесты**
   - `unit/TestCacheManager.cpp`: Тестирование менеджера кэша.
   - `unit/TestConfigManager.cpp`: Тестирование менеджера конфигураций.
   - `unit/TestTokenManager.cpp`: Тестирование менеджера токенов аутентификации.
   - `unit/TestUserDataModels.cpp`: Тестирование моделей данных пользователя.

3. **Интеграционные тесты**
   - `integration/TestApiClient.cpp`: Интеграционные тесты для API клиента.
   - `integration/TestAuthService.cpp`: Интеграционные тесты для сервиса аутентификации.
   - `integration/TestMastergraphService.cpp`: Интеграционные тесты для сервиса Mastergraph (возможно, это часть графического представления данных).

4. **Тесты инженерного клиента**
   - `engineering/TestEngineeringConsole.cpp`: Тестирование консоли инженера.

5. **Основной файл запуска тестов**
   - `test_main.cpp`: Основная точка входа для запуска всех тестов с использованием Google Test и QtTest.

## Ключевые сущности

- **MockApiClient**: Мок-класс API клиента, используемый для имитации запросов к серверу.
- **TestHelpers**: Вспомогательные функции для создания тестовых данных.
- **TokenManager**: Компонент управления токенами аутентификации.
- **AuthService**: Сервис аутентификации и авторизации пользователей.

## API эндпоинты

В модуле `CLIENT/tests` нет прямого определения API эндпоинтов, так как это часть тестов. Однако, в тестах используются следующие эндпоинты:
- `/auth/login`: Для аутентификации пользователя.
- `/auth/password-expiry`: Для проверки срока действия пароля.

## Зависимости от других частей

1. **common/include**: Включает заголовочные файлы общих компонентов клиента, таких как модели данных и интерфейсы сервисов.
2. **UsersServiceClient**: Библиотека клиентского сервиса для взаимодействия с сервером.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский модуль (CLIENT)**: Модуль `CLIENT/tests` является подмодулем клиента и использует общие ресурсы и библиотеки, определенные в корневом каталоге `CLIENT`.
- **Дочерние компоненты**: Внутри модуля `CLIENT/tests` различаются тестовые утилиты, юнит-тесты, интеграционные тесты и специфические тесты для инженерного клиента. Эти компоненты взаимодействуют между собой для выполнения комплексных сценариев тестирования.
