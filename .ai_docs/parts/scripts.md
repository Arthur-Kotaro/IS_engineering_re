# Часть: scripts

## Назначение этой части

Каталог `scripts` содержит различные скрипты, используемые для автоматизации и управления данными в системе ERP для инжиниринговых компаний. Эти скрипты выполняют задачи, связанные с массовым обновлением паролей пользователей, инициализацией тестовых данных и другими административными операциями.

## Основные компоненты и их ответственность

1. **fix_passwords.py**
   - **Ответственность**: Массовое обновление паролей пользователей через bcrypt.
   - **Функциональность**:
     - Подключение к базе данных PostgreSQL.
     - Генерация хеша нового пароля для руководителей.
     - Обновление паролей указанных пользователей в таблице `users`.
     - Проверка длины обновленных хешей.

2. **init_full_test_data.sql**
   - **Ответственность**: Полное заполнение тестовыми данными (роли, подразделения и пользователи).
   - **Функциональность**:
     - Вставка данных в таблицы `roles`, `department` и `users`.
     - Использование конструкции `ON CONFLICT DO NOTHING` для предотвращения дублирования записей.

3. **reset_passwords.sh**
   - **Ответственность**: Массовый сброс паролей через API.
   - **Функциональность**:
     - Получение токена аутентификации для суперадмина.
     - Список пользователей, чьи пароли нужно обновить.
     - Логин как каждый из указанных пользователей и сброс их пароля через API.

## Ключевые сущности

- **Пользователи**: Учетные записи в системе ERP, хранящиеся в таблице `users`.
- **Роли**: Различные роли пользователей (например, администратор системы, руководитель проекта по прототипам), хранящиеся в таблице `roles`.
- **Подразделения**: Организационная структура компании, хранящаяся в таблице `department`.

## API эндпоинты

В рамках этой части скриптов используются следующие API эндпоинты:

1. **POST /login**
   - **Описание**: Получение токена аутентификации.
   - **Параметры запроса**:
     - `email`: Электронная почта пользователя.
     - `password`: Пароль пользователя.

2. **POST /users/me/change-password**
   - **Описание**: Смена пароля текущего пользователя.
   - **Заголовки запроса**:
     - `Authorization: Bearer <token>`: Токен аутентификации.
   - **Параметры запроса**:
     - `current_password`: Текущий пароль пользователя.
     - `new_password`: Новый пароль пользователя.
     - `confirm_password`: Подтверждение нового пароля.

## Зависимости от других частей

- **USER_service**: Взаимодействие с базой данных пользователей для обновления и проверки паролей.
- **API Gateway**: Для доступа к API эндпоинтам, используемым в `reset_passwords.sh`.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительские компоненты**:
  - **API Gateway**: Предоставляет доступ к API эндпоинтам, используемым в `reset_passwords.sh`.
  
- **Дочерние компоненты**:
  - **USER_service**: Взаимодействие с базой данных пользователей для обновления и проверки паролей.

Эти скрипты обеспечивают автоматизацию процессов, связанных с управлением учетными записями пользователей в системе ERP, что упрощает административные задачи и повышает надежность данных.
