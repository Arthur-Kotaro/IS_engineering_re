# Часть: PJP_SERVICE/app/api/v1

## Назначение этой части

Часть `PJP_SERVICE/app/api/v1` отвечает за предоставление API для управления Проектными Жизненными Планами (PJP) и связанными с ними черновиками и документами. Она позволяет создавать, получать, обновлять и удалять черновики проектов, а также публиковать их как окончательные PJP.

## Основные компоненты и их ответственность

1. **draft.py**:
   - Обрабатывает запросы для создания, получения, обновления и удаления черновиков (drafts) проектов.
   - Включает маршруты для работы с частями (parts) черновиков.

2. **pdm.py**:
   - Обрабатывает запросы для управления документами технического производства (PDM).
   - Позволяет загружать и получать документы по их референсному номеру.
   - Включает проверку ролей пользователя для выполнения определенных действий.

3. **pjp.py**:
   - Обрабатывает запросы для получения, обновления статуса и просмотра истории изменений PJP.
   - Позволяет получать части PJP с возможностью фильтрации по различным параметрам.

4. **__init__.py**:
   - Инициализирует модуль `v1` и импортирует основные компоненты (draft, pdm, pjp).

## Ключевые сущности

- **PJPDraft**: Черновик проекта.
- **PJPDraftPart**: Часть черновика проекта.
- **PJP**: Проектный Жизненный План.
- **PJPPart**: Часть PJP.
- **PDMDocument**: Документ технического производства.

## API эндпоинты

### draft.py
1. **POST /drafts**:
   - Создает новый черновик проекта.
   
2. **GET /drafts**:
   - Получает все черновики пользователя.
   
3. **GET /drafts/{draft_id}**:
   - Получает конкретный черновик по его ID.
   
4. **POST /drafts/{draft_id}/parts**:
   - Добавляет часть в черновик проекта.
   
5. **PUT /drafts/{draft_id}/parts/{part_id}**:
   - Обновляет часть в черновике проекта.
   
6. **DELETE /drafts/{draft_id}/parts/{part_id}**:
   - Удаляет часть из черновика проекта.
   
7. **DELETE /drafts/{draft_id}/clear**:
   - Очищает все части черновика проекта.
   
8. **POST /drafts/{draft_id}/publish**:
   - Публикует черновик как окончательный PJP.

### pdm.py
1. **GET /documents/{reference_number}**:
   - Получает документ по его референсному номеру.
   
2. **POST /documents**:
   - Загружает новый документ (только для пользователей с ролью PFE/IST).

### pjp.py
1. **GET /{pjp_id}**:
   - Получает конкретный PJP по его ID.
   
2. **PATCH /{pjp_id}/status**:
   - Обновляет статус PJP.
   
3. **GET /{pjp_id}/parts**:
   - Получает части PJP с возможностью фильтрации.
   
4. **GET /{pjp_id}/history**:
   - Получает историю изменений PJP.

## Зависимости от других частей

- **app.database**: Для взаимодействия с базой данных PostgreSQL.
- **app.schemas.draft**: Схемы для валидации и сериализации данных черновиков.
- **app.services.draft_services**: Сервисные функции для работы с черновиками.
- **app.services.pjp_service**: Сервисные функции для работы с PJP.
- **app.models.pdm**: Модели базы данных для документов технического производства.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский модуль (PJP_SERVICE/app/api)**: Эта часть является подмодулем версии API v1 и взаимодействует с ним через импорт.
- **Дочерние модули**: Внутри этой части находятся отдельные файлы, каждый из которых отвечает за конкретную область функциональности (draft.py, pdm.py, pjp.py).
- **Клиентская часть (CLIENT)**: Через API взаимодействует с этими эндпоинтами для выполнения операций над черновиками и PJP.
- **Другие микросервисы**: Например, USER_service может предоставлять информацию о пользователях и их ролях, используемую в pdm.py для проверки прав доступа.
