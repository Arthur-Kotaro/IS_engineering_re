# Часть: CLIENT/tests/unit

## Назначение этой части

Каталог `CLIENT/tests/unit` содержит модульные тесты для компонентов клиента ERP системы, разработанной на основе Qt/QML. Эти тесты обеспечивают проверку функциональности отдельных классов и методов без необходимости запуска всей системы или взаимодействия с внешними сервисами.

## Основные компоненты и их ответственность

1. **TestCacheManager.cpp**
   - **Ответственность:** Тестирует функциональность кэширования данных, используя фреймворк Google Test (gtest).
   
2. **TestConfigManager.cpp**
   - **Ответственность:** Проверяет работу менеджера конфигурации приложения.
   
3. **TestTokenManager.cpp**
   - **Ответственность:** Тестирует класс `TokenManager`, который управляет доступными и обновлёнными токенами аутентификации.
   
4. **TestUserDataModels.cpp**
   - **Ответственность:** Проверяет сериализацию и десериализацию моделей данных пользователей, таких как `ProjectRole` и `UserInfo`.

## Ключевые сущности

- **CacheManager**: Предполагается, что это класс для управления кэшированием данных.
- **ConfigManager**: Менеджер конфигурации приложения, отвечающий за загрузку и сохранение настроек.
- **TokenManager**: Класс для работы с токенами аутентификации, включая их установку, обновление, очистку и проверку сроков действия.
- **ProjectRole**: Модель данных, представляющая роль пользователя в проекте.
- **UserInfo**: Модель данных, содержащая информацию о пользователе.

## API эндпоинты

В этой части нет прямого взаимодействия с внешними сервисами или базой данных, поэтому API эндпоинтов отсутствуют. Однако тесты могут использовать моки для имитации вызовов к этим ресурсам.

## Зависимости от других частей

1. **CLIENT/common**: Содержит заголовочные файлы и реализацию классов, которые используются в тестах (например, `TokenManager`, модели данных).
2. **Третье-party библиотеки**: Google Test (gtest) и Google Mock (gmock) для написания и запуска модульных тестов.
3. **Qt Framework**: Используется для работы с JSON (`QJsonObject`), датами (`QDateTime`) и другими функциональными возможностями.

## Взаимодействие с родительскими/дочерними компонентами

- **Родительский каталог (CLIENT/tests)**: `CLIENT/tests/unit` является подкаталогом, содержащим модульные тесты. Родительский каталог может также содержать другие типы тестов, такие как интеграционные или функциональные.
- **Дочерние компоненты**: Внутри текущего каталога нет дополнительных подкаталогов, все файлы являются непосредственными модульными тестами.

Эта структура позволяет легко добавлять новые тесты для новых или изменённых компонентов клиента ERP системы, обеспечивая высокое качество и надёжность кода.
